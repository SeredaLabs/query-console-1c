# A1.3 — token-backed top-level comma detection

Historical slice report. Its raw-fallback policy was subsequently replaced by
the [expression lexical contract](../expression-lexical-contract.md).

Baseline: `5b84c1b`. This slice changes only `hasTopLevelComma` in
`sdblGenerator.ts`; A1 remains open. Its consumers are DCS virtual-table
parameter wrapping/aliasing, tuple NOT membership and JOIN NOT-operand grouping.

The scanner now reads punctuation from `sdblLexer` tokens. Parenthesis depth,
including negative/unbalanced depth, is unchanged; braces and square brackets
still do not contribute depth. Lexer-rejected input uses the unchanged former
scanner. The helper is exported for tests, following the preceding A1 slices.

## Behavior and evidence

- Ordinary lists, nested calls, quoted strings and escaped quotes retain their
  results. Direct tests also lock incomplete-input fallback behavior.
- Commas and parentheses inside date tokens and line comments no longer count
  as code. Example: `'a,b'` changes from list to non-list; `А // ,` does likewise.
- A reachable manual JOIN expression `НЕ (Т.А = 'a,b')` now renders as
  `(НЕ Т.А = 'a,b')` instead of `(НЕ(Т.А = 'a,b'))`. This exercises lexical
  boundaries, not a claim that the date is platform-valid. No validation or
  Apply rule changes. JOIN line comments retain their existing bypass.
- Before/after generation of all 1976 committed corpus queries is byte-identical
  both with and without the committed YAML resolver: **0 changed outputs**.
- A temporary differential probe compared the previous and new helpers on 3840
  combinations of atoms, separators and wrappers. 348 results differed, all on
  inputs containing date literals or line comments. All 1945 lexer-rejected
  inputs retained their result. This is bounded synthetic evidence, not an
  exhaustive proof of behavior preservation.
- No fixtures, snapshots, golden records or classification baselines changed.
