# Границы и гарантии ядра

Статус: **операционный документ**. Обновляется вместе с изменениями, которые
влияют на безопасное открытие, редактирование или генерацию SDBL.

Это расширение не является полным компилятором BSL или SDBL. Перед применением
ручных правок важно различать поддержанное поведение, частичную валидацию и
известные ограничения.

## Безопасное использование

- Генерация запросов, созданных в визуальном конструкторе, покрыта unit- и
  corpus-регрессией.
- Открытие существующего текста проверяет структуру SDBL и, при наличии cache,
  существование таблиц. Это не полная проверка выражений, полей, навигации через
  точку или платформы 1С.
- Поиск запроса под курсором работает только для статических BSL-строк, которые
  после комментариев и пробелов начинаются с `ВЫБРАТЬ` или `УНИЧТОЖИТЬ`.
  Динамические запросы, англоязычный синтаксис и произвольные BSL-конструкции не
  распознаются.
- После изменения XML-выгрузки нужно нажать **«Обновить кэш»** или выполнить
  команду `1С: Распарсить метаданные в YAML`. Текущий cache не сверяется с XML
  автоматически.

## Ограничения, блокирующие lossless round-trip

Не используйте конструктор для сохранения запросов с такими источниками до
исправления соответствующего дефекта:

- Виртуальные таблицы с тремя и более параметрами, попадающие в общий fallback:
  `РегистрРасчета.*.ДанныеГрафика`,
  `РегистрРасчета.*.ФактическийПериодДействия`,
  `Последовательность.*.Границы`.
  До 2 параметров включительно -- lossless.

(`РегистрБухгалтерии.<Имя>.Субконто(...)` и позиционный аргумент `ВидыСубконто`
у `Остатки`/`Обороты`/`ОборотыДтКт`/`ОстаткиИОбороты` -- тот же класс дефекта,
исправлен: PR-04, `test/unit/virtualTableRoundTrip.test.ts`.)

Детали, статус и ссылки на код -- в [KNOWN_ISSUES.md](KNOWN_ISSUES.md). До
исправления не применяйте изменения через конструктор для этих форм; защита UI
(read-only или отказ в применении) ещё не реализована.

## Границы валидации

Рукописный parser допускает непрозрачные `custom`-выражения, чтобы не ограничивать
поддержку функций SDBL. Поэтому успешный `parseBatch` не доказывает, что каждое
выражение синтаксически примет платформа 1С. Имеющиеся структурные проверки ловят
часть ошибок порядка секций и недоразобранного хвоста, но не заменяют полную
грамматику или `1c-md.validate_query`.

Независимый tree-sitter oracle выполняется только когда локально собран
`test/fixtures/tree-sitter-sdbl.wasm`; текущий CI не поставляет этот артефакт.
Воспроизводимый CI-gate -- `npm run typecheck`, `npm run test:unit` и
`npm run test:e2e`; он не является сертификацией полной совместимости с 1С.
