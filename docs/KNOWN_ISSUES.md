# Известные проблемы

Статус: **операционный backlog**. Здесь фиксируются подтверждённые неисправленные
дефекты, а не исторические предположения. Приоритеты работ -- в
[ROADMAP.md](ROADMAP.md); безопасное поведение до исправления -- в
[CORE_LIMITATIONS.md](CORE_LIMITATIONS.md).

## Критические: возможна тихая потеря данных или ложное подтверждение корректности

- **Tolerant parser может принять ошибочное выражение.** `parseBatch` сохраняет
  нераспознанные части как `custom`-текст; поэтому `validateBatchText` может
  разрешить «Применить» для синтаксически неверного оператора или функции. Нужен
  strict expression validator либо внешний grammar/oracle gate для этого сценария.
  Владельцы: `src/core/query/sdblParser.ts`, `validateBatch.ts`.
  (`РегистрБухгалтерии.*.Субконто` и безымянный слот `ВидыСубконто` у
  `Остатки`/`Обороты`/`ОборотыДтКт`/`ОстаткиИОбороты` — тот же класс бага,
  уже исправлен в PR-04: `accountingPositionKeys`/`accountingParamFields` в
  `queryModel.ts`/`accountingVirtualParams.ts`, покрыт
  `test/unit/virtualTableRoundTrip.test.ts` и `accountingVirtualParams.test.ts`.)

## Высокие: неверная модель, неполная проверка или отсутствие test gate

- **Cache метаданных может быть устаревшим (исправлено, PR-10 + остаточный
  случай).** На ОСНОВНОМ пути (`loadMetadataSnapshotFirst`, задействован при
  любом заданном `cfPath` — см. PR-10 widen) устаревший снимок обнаруживается:
  mtime закоммиченного снимка сравнивается с mtime XML-файлов в 17 распознаваемых
  подкаталогах (`newestRelevantMtime`, `loadMetadataSafe.ts`) — при более новом
  XML происходит rebuild, а не тихая выдача старых данных. Подтверждено вручную
  на двух реальных конфигурациях (изменение mtime реального XML-файла
  корректно триггерит rebuild). Остаточная ветка (`panel.ts`'s `loadMetadata`,
  срабатывает ТОЛЬКО когда И direct-путь, И его YAML-откат уже оба упали)
  теперь ТОЖЕ сравнивает mtime `configuration.yaml` с `newestRelevantMtime(cfPath)`
  (той же экспортированной функцией) и явно логирует предупреждение в output
  channel, если XML новее — вместо тихой выдачи устаревших данных как
  актуальных. Пересборку эта ветка не форсирует (обе попытки уже провалились
  выше по стеку — повторный вызов провалился бы так же), только делает
  устаревание видимым. Автотест для самой freshness-функции: `newestRelevantMtime`
  в `loadMetadataSafe.test.ts`; сама ветка `panel.ts` покрыта Extension Host
  тестом (`test/vscode-integration/metadataPipeline.test.ts`, см. ниже).
  Единственный оставшийся случай без freshness-проверки: `cfPath` вообще не
  задан (нет источника XML для
  сравнения — это архитектурный предел, не дефект). Владелец:
  `src/extension/panel.ts`, `src/core/metadata/parser/loadMetadataSafe.ts`.
- **Неполная поддержка metadata reference types.** `typeParser.ts` распознаёт
  только часть ссылок 1С; неизвестные виды теряются как пустой тип. Владельцы:
  `src/core/metadata/parser/typeParser.ts`, `yamlLoader.ts`.
- **Локальная семантика не проверяет поля и навигацию.** Проверяется существование
  таблиц, но не реквизиты, поля и обращения через точку. Владелец:
  `src/core/query/semanticValidator.ts`.
- **План обмена `*.Изменения` даёт ложный semantic failure.** Подтаблица не
  представлена в YAML-cache, поэтому полный semantic прогон нельзя сделать жёстким
  CI-gate. Владельцы: metadata parser и `semanticValidator.ts`.
- **Extension Host integration test (исправлено, частично).** `npm run test:integration`
  (`@vscode/test-cli`/`@vscode/test-electron`, `test/vscode-integration/`) теперь
  запускает НАСТОЯЩИЙ VS Code с расширением: регистрация команд, реальная
  сборка metadata из XML через реальный `vscode` API, реальная замена
  BSL-литерала в `vscode.TextDocument` (включая staleDocument-защиту) — всё
  покрыто. НЕ покрыто этим же изменением: содержимое сообщений host ↔ webview
  (`ready`/`metadataTree`/...) — публичный `vscode` API не даёт тестовому коду
  доступ к уже созданной команды `WebviewPanel`, поэтому пока остаётся только за
  `npm run test:e2e` (Playwright, статический harness с мок `vscode` API,
  UI-уровень, не проверка интеграции). Владелец: `test/vscode-integration/`.
- **Независимая tree-sitter SDBL-проверка не работает в CI.** WASM-грамматика не
  коммитится и не собирается release workflow; локальный oracle не является CI-gate.

## Средние

- **Параметры некоторых виртуальных таблиц теряются при `parse -> generate`
  (риск подтверждён реальными данными как низкий, не критический).**
  Формы с потенциально тремя и более аргументами (`РегистрРасчета.*.ДанныеГрафика`,
  `ФактическийПериодДействия`, `Последовательность.*.Границы`) попадают в общий
  `[period, condition]` fallback (`parseVirtualParams`, `sdblParser.ts`) — 3-й и
  последующие аргументы молча потерялись бы; ≤2 аргументов — LOSSLESS.
  Раньше это числилось в «Критических» без реальной проверки. 2026-09-05
  проверено на ДВУХ независимых реальных production-конфигурациях пользователя
  (не в репозитории): (1) ручной просмотр всех ~12 реальных вызовов этих трёх
  форм в Overtrans (модуль расчёта зарплаты + партионный учёт) — ни одного
  вызова с 2+ аргументами, `ДанныеГрафика`/`ФактическийПериодДействия` всегда
  0 или 1 (условие), `Границы` всегда без скобок вовсе (0 аргументов) — что
  совпадает с документированным синтаксисом платформы 1С для этих конкретных
  виртуальных таблиц (у них структурно нет слота "период", только один
  необязательный `<Условие>`, а у `Границы` параметров нет вообще); (2)
  автоматизированное сканирование ВСЕХ извлечённых запросов из обеих
  конфигураций (`extractQueryStrings` + `parseBatch` + `findUnsafeVirtualTables`,
  тот же код, что использует `App.tsx`) — 0 срабатываний `unsafeExtraArgs` на
  ~4347 успешно распарсенных реальных запросах (SFK: 1626 извлечено, 115 не
  распарсились и не в счёт; Overtrans: 3830 извлечено, 994 не в счёт). SFK не
  содержит регистров расчёта/последовательностей вовсе, поэтому релевантен
  только Overtrans. Само искажение параметров при parse→generate НЕ исправлено
  (raw-позиции просто не помечены семантически верными именами полей внутри
  `VirtualParams`) — но это не влияет на round-trip (generate печатает позиции
  как есть, независимо от внутреннего имени поля), поэтому это не баг
  сохранности данных для НАБЛЮДАЕМЫХ реальных случаев, только теоретический для
  ещё не встреченного 3-го аргумента. Apply-blocking (PR-05, `unsafeExtraArgs`)
  остаётся как defense-in-depth на случай, если такой пример всё же найдётся.
  Синтетический corpus (`test/fixtures/corpus/meta1c/`) НЕ содержит фикстур для
  регистров расчёта/последовательностей вовсе — этот класс форм не покрыт
  автоматическим regression-тестом, только разовой ручной проверкой выше.
  Владельцы: `src/core/query/sdblParser.ts`, `semanticValidator.ts`.
- Запись JSON-side-кэшей (`cacheBuilder.ts`, `modelCache.ts`) неатомарна: падение
  посреди записи оставляет повреждённый файл без понятной диагностики (сама YAML-
  генерация уже защищена staged-build + logical commit — PR-02, см. ниже).
- Symlink-каталоги не находятся auto-discovery (`resolveCfPath.ts` /
  `findCfRoot.ts`).
- `RENAME_QUERY` не сбрасывает комментарии участника `ОБЪЕДИНЕНИЕ`; влияние пока
  не подтверждено, но поведение не имеет regression-теста.

## Низкие / для наблюдения

- `generate`/`generatedText` в `src/shared/messages.ts` -- мёртвый message pair.
- Fallback `insertResult.ts` срабатывает также при переключении неактивной вкладки,
  а не только когда редактор закрыт.
- После долгого `await metadataReady` `panel.ts` теоретически может отправить
  сообщение уже закрытой панели; это ещё не подтверждено runtime-воспроизведением.

исправления его удаляют отсюда, добавляют regression-тест и при необходимости
обновляют [CORE_LIMITATIONS.md](CORE_LIMITATIONS.md).
