# Известные проблемы (бэклог)

Подтверждённые находки, которые НЕ исправлены в рамках текущей стабилизационной
итерации (2026-09-03) — зафиксированы здесь, чтобы не потерять, без обязательства
браться за них немедленно. Каждый пункт — с местом, откуда он взят, и статусом.

См. также: [ROADMAP](ROADMAP.md), [PHASE_9](PHASE_9.md) (что уже исправлено в этой
итерации: 3 критических бага парсера, 2 бага reducer'а `queryStore`, устаревшие
смещения при вставке — см. коммиты `20cef22`, `8ecc6c3`, `34afc79`, `8caf70f`).

## Критические (данные/семантика теряются молча)

- **`РегистрБухгалтерии.X.Субконто(&Период, &Условие)` теряет ОБА параметра** при
  цикле разбор → генерация (`accountingPositionKeys` не знает слайс `Субконто`,
  `sdblParser.ts`/`queryModel.ts`). Найдено сверкой с грамматикой `1c-syntax/
  bsl-parser`, подтверждено эмпирически (`tryOpenBatch`/`generateDocument`).
  Латентный вариант того же класса: 3+ аргумента у `РегистрРасчета.
  ДанныеГрафика`/`ФактическийПериодДействия`/`Последовательность.Границы`
  попадают в общий `[period, condition]`-фолбек и могут сместиться.

## Высокие

- **Кеш метаданных не сверяется с реальным XML-экспортом** — `panel.ts` доверяет
  кешу, если `configuration.yaml` просто существует; подмена конфигурации без
  удаления кеша молча обслуживает старую модель.
- **`typeParser.ts` распознаёт только 3 из ~9 видов ссылок** (`BusinessProcessRef`/
  `TaskRef`/`ExchangePlanRef`/`ChartOfAccountsRef`/… отпадают в пустой тип,
  `yamlLoader.ts`'s `mapParsedType` отбрасывает `raw`-строку без следа).
- **Автоопределение `cf`-каталога не видит symlink** (`resolveCfPath.ts`/
  `findCfRoot.ts` — `Dirent.isDirectory()` возвращает `false` для symlink-директорий).
- **Полный прогон `validateBatchSemantics` по золотому корпусу даёт 4 (0.2%)
  настоящих ложных срабатывания** — `<Тип>.<Объект>.Изменения` (подтаблица
  регистрации изменений плана обмена) отсутствует в YAML-кеше метаданных. Блокирует
  оформление такого прогона в жёсткий CI-гейт, пока не исправлено (см. PHASE_9.md).
- **Проверка полей/реквизитов/навигации через точку отсутствует в
  `semanticValidator.ts`** — и `bsl-language-server`'s `QueryToMissingMetadata`, и
  MCP `1c-md.validate_query` это делают, мы — нет (задокументированная, осознанная
  прогалина, см. PHASE_8.4 §«Объём и границы»).

## Средние

- `parseConfiguration.ts`: запись YAML-объекта (`writeYaml`) — ВНЕ try/catch,
  которым обёрнут сам разбор; повреждённое/некорректное имя объекта в XML может
  прервать парсинг ВСЕЙ конфигурации вместо одного объекта.
- Запись кеша метаданных (`cacheBuilder.ts`, `parser/yamlWriter.ts`) не атомарна
  (нет temp-файл-затем-rename) — падение процесса мидзаписи оставляет обрезанный
  файл. Не критично (оба читателя fail-safe: битый JSON → просто пересборка), но
  без явного уведомления пользователя.
- `RENAME_QUERY` (`queryStore.ts`) не сбрасывает комментарии участника объединения —
  расхождение с задокументированной политикой (PHASE_8.md §«ОБЪЕДИНЕНИЕ»:
  переименование должно сбрасывать комментарии, как и для пакета). Практический
  эффект, вероятно, нулевой (`meta.name` не попадает в генерируемый SQL), но не
  протестировано explicitly.
- `docs/PHASE_8.md` §«Объём и границы» утверждает, что стандартные поля
  (`Ссылка`/`Код`/…) ОТСУТСТВУЮТ в `MetaTable.fields` и синтезируются только при
  `*`-раскрытии — по факту парсеры (`catalog.ts`, `document.ts` и т.д.) кладут их
  туда напрямую; `buildSelectAllModel.ts` лишь фильтрует/переупорядочивает. Документ
  расходится с кодом — стоит перепроверить перед тем, как опираться на это описание
  при развитии проверки полей (пункт выше).
- Независимый tree-sitter-оракул (`assertValidSdbl`, `test/helpers/`) не запускается
  в CI (`.wasm`-грамматика не коммитится и не собирается в `release.yml`) — реальная
  проверка «третьей независимой грамматикой» существует только локально у
  разработчика, что расходится с тем, как это описано в документах.
- Цифра «17933 запроса, 0 mismatch» (`ROADMAP.md`/`PHASE_6.md`, фаза 6.19) —
  одноразовый исторический прогон против второй конфигурации, файл которой
  отсутствует в репозитории; не воспроизводимый CI-гейт (в отличие от 1976-корпуса
  в `corpusRegression.test.ts`). Формулировку в документах стоит уточнить.

## Низкие / наблюдения

- Мёртвая пара сообщений `generate`/`generatedText` в `src/shared/messages.ts` —
  webview никогда не отправляет `generate`, `panel.ts` реализует ответ, которым
  никто не пользуется.
- Fallback вставки результата (`insertResult.ts`) срабатывает и при переключении
  вкладки редактора (не только при её закрытии) — `vscode.window.visibleTextEditors`
  не включает неактивную вкладку той же группы. Не баг per se, но недокументированное
  поведение.
- Нет отслеживания `panel.onDidDispose` в `panel.ts` — гипотетическая (не
  подтверждённая статическим чтением) отправка `postMessage` в уже закрытую панель
  после долгого `await metadataReady`.
