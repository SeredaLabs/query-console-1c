## ⚙️ Настройка источника

`queryConsole.metadataPath` принимает абсолютный путь к каталогу `cf` файловой
XML-выгрузки 1С. Если значение пусто, расширение сначала проверяет `src/cf`
каждой рабочей области, затем ищет `Configuration.xml` до глубины шести каталогов.

Основной импортёр читает поддерживаемые виды объектов и общие реквизиты
непосредственно из XML и фиксирует сводный JSON-снимок в
`queryConsole.parserOutputPath`; промежуточный YAML при этом не создаётся. Если
этот путь завершается ошибкой, расширение прозрачно перестраивает метаданные
старым YAML-конвейером. YAML — резервный путь совместимости, а не обычный путь
загрузки.

## 🔄 Создание или обновление кеша

Выполните **1С: Перестроить индекс метаданных** из палитры команд или нажмите
**Обновить кэш** в Classic — оба варианта перестраивают одинаково. Индекс
сверяется со временем изменения XML-выгрузки и перестраивается автоматически,
когда устарел; ручное обновление нужно только чтобы форсировать пересборку
раньше, либо когда изменение не заметили ни палитра команд, ни конструктор
(например, выгрузку заменили через инструмент синхронизации, сохраняющий
временные метки файлов).

Результат можно воспроизвести, и он не заменяет исходный XML. Импортёр сначала
готовит новое поколение и не удаляет каталог, которым не владеет.

Если и прямой импорт, и YAML-резерв завершились ошибкой, расширение может
использовать последнюю непустую модель из хранилища расширения VS Code.
Успешное сканирование с нулём таблиц честно показывается для текущего вызова,
а не подменяется старыми данными; оно не перезаписывает сохранённый
last-known-good, а следующая загрузка снова сканирует источник.

## 🔍 Поведение поиска

Поиск сопоставляет несколько слов с нормализованными именами. Нет нечёткого
исправления опечаток; отсутствующие в выгрузке или неподдерживаемые типы не
появятся. Временные таблицы текущего пакета показаны отдельно.
