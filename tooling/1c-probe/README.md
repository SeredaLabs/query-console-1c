# Внешняя обработка: проверка запросов на платформе

`ПроверкаЗапросовНаПлатформе.epf` проверяет тексты запросов на той версии
платформы 1С, где она открыта, и выдаёт результат текстом — по одной строке JSON
на запрос. С её помощью подтверждают конструкции, которые недоступны на
платформе, подключённой к разработке через MCP (8.3.15): результаты становятся
фикстурами `test/fixtures/platform/*.json` и пунктами
[реестра](../../docs/development/technical-debt.md).

Запросы **не выполняются**: проверяются только разбор и компиляция, данные базы
не читаются и не изменяются. Обработку можно открывать в рабочей базе.

## Быстрый старт

1. Скопируйте на компьютер с нужной версией платформы два файла:
   `ПроверкаЗапросовНаПлатформе.epf` и пакет проб, например
   [`probes-8.3.15-refused.txt`](probes-8.3.15-refused.txt). Скачивайте их из
   репозитория (`git pull` или «Download raw file» на GitHub): при пересылке через
   мессенджер файл может прийти повреждённым.
2. Запустите базу в режиме «1С:Предприятие» **на нужной версии платформы**
   (версия задаётся в настройках базы в списке баз, поле «Версия
   1С:Предприятия»).
3. **Файл → Открыть** → `ПроверкаЗапросовНаПлатформе.epf`; подтвердите
   предупреждение безопасности, если оно появится.
4. Кнопкой «…» у поля **Файл запросов** выберите пакет проб, у поля **Файл
   результата** — куда сохранить результат (например, `probes-result.jsonl`).
5. Нажмите **Проверить**. Появится «Проверено запросов: N.», результат будет в
   поле **Результат** и в файле.
6. Проверьте, что в результате `"platformBuild"` — нужная версия, и передайте файл
   результата в репозиторий (см. [Что делать с результатом](#что-делать-с-результатом)).

Один запрос можно проверить без файлов: вставьте его в поле **Текст запросов**,
оставьте **Файл запросов** пустым и нажмите **Проверить**.

## Поля формы

| Поле | Назначение |
|---|---|
| Файл запросов | Пакет проб (UTF-8; ANSI и UTF-16 распознаются). Если указан, поле «Текст запросов» не используется. |
| Файл результата | Куда записать результат (UTF-8). Если пусто, результат только в поле «Результат». |
| Текст запросов | Запросы, вставленные вручную, в том же формате, что и файл. |
| Результат | Результат проверки, только для чтения. |

## Формат пакета проб

Каждый запрос начинается строкой `//# <имя пробы>`; всё до следующей такой строки —
текст запроса. Блок только из комментариев и пустых строк (например, шапка файла)
пропускается. Текст без строк `//#` — один запрос с именем `query`.

```
// Шапка: что за пакет, откуда пробы.
//# PQ-expression.math-functions.acos
ВЫБРАТЬ
	ACOS(0.5) КАК Ф1
ИЗ
	РегистрСведений.КурсыВалют КАК К
//# PQ-group.grouping-sets.1
ВЫБРАТЬ …
```

Пробы ссылаются на объекты конфигурации. Если объекта в базе нет, ответ будет
«Таблица не найдена» — это свойство базы, а не вердикт о версии платформы.

## Что проверяется

Для каждого запроса, на сервере:

1. **Как «Конструктор запроса»** — `СхемаЗапроса.УстановитьТекстЗапроса(Текст)`;
   при успехе сохраняется канонический текст `СхемаЗапроса.ПолучитьТекстЗапроса()`
   (тот же текст, что печатает конструктор).
2. **Как исполнение** — `Запрос.НайтиПараметры()`: компиляция без выполнения
   (синтаксис и имена метаданных).

## Формат результата

Одна строка JSON на запрос (JSON Lines):

| Поле | Значение |
|---|---|
| `name` | имя пробы |
| `platformBuild` | версия платформы (`СистемнаяИнформация.ВерсияПриложения`) |
| `platformDate` | дата проверки |
| `query` | исходный текст |
| `designerOk` / `designerError` | принят ли текст схемой запроса / текст ошибки |
| `query_text` | канонический текст схемы запроса (если принят) |
| `compileOk` / `compileError` | компилируется ли запрос / текст ошибки |
| `valid` | приняты оба шага |

## Что делать с результатом

Передайте файл результата вместе с названием и версией конфигурации базы
(«Справка → О программе») и списком её расширений. Из него собирается фикстура
`test/fixtures/platform/<пакет>-<версия>.json` (пример:
[`v5-phase5-8.5.1.1529.json`](../../test/fixtures/platform/)) с тестами на
совпадение нашего текста с каноническим текстом платформы.

## Если что-то не так

| Симптом | Причина и что сделать |
|---|---|
| В результате квадратики вместо кириллицы, все запросы — «Синтаксическая ошибка» в (1, 1) | Файл прочитан не в той кодировке. Текущая версия обработки распознаёт UTF-8, ANSI и UTF-16; если ошибка осталась — сохраните пакет в UTF-8. |
| «Файл запросов содержит нулевые символы» или «Текст XML содержит недопустимые символы» | Файл повреждён (например, не докачан). Скачайте его заново из репозитория. |
| `platformBuild` — не та версия | База запущена на другой платформе: выберите версию в настройках базы. |
| Проверено меньше запросов, чем в пакете | Проверьте, что каждая проба начинается строкой `//#` в начале строки. |
| «Таблица не найдена» | В базе нет объекта из пробы; на версию это не указывает. |

## Как собрать обработку из исходника

Готовая `.epf` лежит рядом. Собирать заново нужно, только если меняется модуль
[`ПроверкаЗапросовНаПлатформе.bsl`](ПроверкаЗапросовНаПлатформе.bsl) — после
правки модуля обновите и `.bsl`, и `.epf`.

1. Конфигуратор: **Файл → Новый → Внешняя обработка**. Имя:
   `ПроверкаЗапросовНаПлатформе`, синоним: «Проверка запросов на платформе».
2. **Формы → Добавить** → «Форма обработки», основная.
3. На вкладке **Реквизиты** формы добавьте четыре реквизита типа «Строка» длиной
   `0` (неограниченная): `ТекстЗапросов`, `ФайлЗапросов`, `ФайлРезультата`,
   `Результат`.
4. Перетащите реквизиты в дерево элементов. Для `ТекстЗапросов` и `Результат`
   включите **Многострочный режим**; для `Результат` — ещё **Только просмотр**.
5. На вкладке **Команды** добавьте команду `Проверить` с действием `Проверить` и
   перетащите её на форму.
6. Для полей `ФайлЗапросов` и `ФайлРезультата` включите **Кнопка выбора** и
   создайте обработчики события **НачалоВыбора** (`ФайлЗапросовНачалоВыбора`,
   `ФайлРезультатаНачалоВыбора`).
7. Замените модуль формы кодом из `ПроверкаЗапросовНаПлатформе.bsl`; **Модуль →
   Проверить синтаксис**.
8. **Файл → Сохранить как…** → `ПроверкаЗапросовНаПлатформе.epf`.

## Состав каталога

- `ПроверкаЗапросовНаПлатформе.epf` — готовая обработка.
- `ПроверкаЗапросовНаПлатформе.bsl` — исходник её модуля формы.
- `probes-8.3.15-refused.txt` — 44 пробы, отклонённые 8.3.15.1489 (V5 phase 5 и
  C40); результаты на 8.5.1.1529 — `test/fixtures/platform/v5-phase5-8.5.1.1529.json`.
