# Внешняя обработка: проверка запросов на платформе

Внешняя обработка 1С `ПроверкаЗапросов` проверяет тексты запросов на той версии
платформы, где она открыта, и выдаёт результат текстом — по одной строке JSON на
запрос. Нужна, чтобы подтвердить конструкции, которые доступная через MCP
платформа (8.3.15.1489) не принимает: результаты переносятся в
`test/fixtures/platform/*.json` и реестр (V5, C40, C49).

Запросы **не выполняются**: проверяется только разбор и компиляция, данные базы
не читаются и не изменяются.

## Что проверяется

Для каждого запроса, на сервере:

1. **Как «Конструктор запроса»** — `СхемаЗапроса.УстановитьТекстЗапроса(Текст)`;
   при успехе сохраняется канонический текст `СхемаЗапроса.ПолучитьТекстЗапроса()`
   (тот же текст, что печатает конструктор и возвращает `validate_query`).
2. **Как исполнение** — `Запрос.НайтиПараметры()`: компиляция без выполнения
   (синтаксис и имена метаданных).

## Формат входа

Запросы текстом в поле формы или файлом UTF-8 (файл в ANSI/Windows-1251
распознаётся по символам замены и перечитывается). Несколько запросов разделяются
строкой, которая начинается с `//#`, за ней — имя пробы. Блок только из
комментариев и пустых строк (например, шапка файла) пропускается.

```
//# PQ-expression.math-functions.acos
ВЫБРАТЬ
	ACOS(0.5) КАК Ф1
ИЗ
	РегистрСведений.КурсыВалют КАК К
//# PQ-group.grouping-sets.1
ВЫБРАТЬ …
```

Готовый пакет: [`probes-8.3.15-refused.txt`](probes-8.3.15-refused.txt) — все 44
запроса, которые 8.3.15.1489 отклонила (V5 phase 5 и C40). В них объекты
конфигурации SL_kza (`Справочник.Валюты`, `РегистрСведений.КурсыВалют`,
`Документ.Встреча`, …): на базе без таких объектов ответ будет «Таблица не
найдена», и это не вердикт о версии.

## Формат результата

Одна строка JSON на запрос (JSON Lines), в поле «Результат» и в файле, если он
указан:

| Поле | Значение |
|---|---|
| `name` | имя пробы |
| `platformBuild` | версия платформы (`СистемнаяИнформация.ВерсияПриложения`) |
| `platformDate` | дата проверки |
| `query` | исходный текст |
| `designerOk` / `designerError` | принят ли текст схемой запроса / ошибка |
| `query_text` | канонический текст схемы запроса (если принят) |
| `compileOk` / `compileError` | компилируется ли запрос / ошибка |
| `valid` | приняты оба шага |

## Как собрать обработку (Конфигуратор, один раз)

`.epf` — двоичный файл, поэтому в репозитории лежит исходник модуля формы
[`ПроверкаЗапросов.bsl`](ПроверкаЗапросов.bsl). Обработку собирают в
Конфигураторе нужной версии платформы:

1. **Файл → Новый → Внешняя обработка**. Имя: `ПроверкаЗапросов`.
2. **Формы → Добавить** → «Форма обработки», основная.
3. В форме, на вкладке **Реквизиты**, добавьте четыре реквизита типа «Строка»
   с длиной `0` (неограниченная): `ТекстЗапросов`, `ФайлЗапросов`,
   `ФайлРезультата`, `Результат`.
4. Перетащите реквизиты в дерево элементов формы. Для `ТекстЗапросов` и
   `Результат` включите свойство **Многострочный режим**; для `Результат` —
   ещё **Только просмотр**.
5. На вкладке **Команды** добавьте команду `Проверить`; в свойстве **Действие**
   создайте обработчик (процедура `Проверить`). Перетащите команду на форму —
   появится кнопка.
6. Для полей `ФайлЗапросов` и `ФайлРезультата` включите свойство **Кнопка
   выбора** и создайте обработчик события **НачалоВыбора** (кнопка с лупой в
   палитре свойств) — платформа создаст процедуры `ФайлЗапросовНачалоВыбора` и
   `ФайлРезультатаНачалоВыбора`; их тело придёт из модуля на следующем шаге.
   Кнопка «…» открывает диалог выбора файла (для результата — диалог
   сохранения).
7. Откройте **Модуль** формы и замените его содержимое кодом из
   `ПроверкаЗапросов.bsl`.
8. **Файл → Сохранить как…** → `ПроверкаЗапросов.epf`.

## Как запустить

1. Откройте базу на нужной версии платформы в режиме «1С:Предприятие».
2. **Файл → Открыть** → `ПроверкаЗапросов.epf` (подтвердите предупреждение
   безопасности, если появится).
3. Укажите `ФайлЗапросов` — путь к `probes-8.3.15-refused.txt` (или вставьте
   запросы в поле «Текст запросов»), и `ФайлРезультата` — например,
   `C:\temp\probes-result.jsonl`.
4. Нажмите **Проверить**. Пути к файлам — на компьютере, где открыт клиент.

Файл результата переносится в репозиторий (например, как
`test/fixtures/platform/v5-phase5-<версия>.json`) вместе с версией платформы и
конфигурацией базы.

## Состав каталога

- `ПроверкаЗапросов.bsl` — исходник модуля формы.
- `probes-8.3.15-refused.txt` — пакет проб, отклонённых 8.3.15.1489.
